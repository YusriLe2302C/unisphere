# UniSphere frontend API contract audit

Date: 2026-11-14

This audit maps frontend service calls to the checked-in Express route modules and their response envelopes. It is a source-level contract check. The currently reachable API at `localhost:5000` is not the checked-in backend, so response behavior from that instance cannot validate these contracts.

## Contract map

All paths below are relative to `/api`. Authenticated JSON calls use `Authorization: Bearer <JWT>` through `apiRequest`. Uploads send multipart `file` plus the documented metadata fields. File downloads return binary content and use a bearer header.

## Executed API probes

Read-only probes were sent to the active `http://localhost:5000` service: health, auth current-user, a unique no-match user search, research list/search, collaborations list, opportunities search, notifications/preferences, events/calendar, timetable, announcements, admin stats, conversations, career questions, and my applications. The health route returned `{ "status": "ok" }`; `/api/docs.json` returned 404. Most checked-in route paths returned 404, and `/api/users` returned 401 without a token. The checked-in `backend/src/app.ts` instead returns a different health object, exposes `/api/docs.json`, and mounts the listed route families.

The backend’s `tsx` development runner is not installed in this workspace, so I could not start the checked-in backend against an isolated database. No login/demo credentials or existing user records were used, and no mutating API calls were sent. As a result, authenticated success envelopes, role permissions, upload round trips, and workflow writes remain **not live-verified**. They were compared against route/controller source only.

## Corrections made during this audit

- Event-registration notification `entityId` values are registration IDs (some include a suffix), not event IDs. Those notifications now lead to the registered-events route. Legacy schedule-change IDs can represent posts as well as events; they now lead to the event listing instead of constructing a possibly invalid event-detail URL.
- Authenticated file downloads and protected avatar fetches now invoke the same 401 session-expiration handler as JSON requests.
- Research download object URLs are revoked after the browser has had time to begin the download.
